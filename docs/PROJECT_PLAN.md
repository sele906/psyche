# psyche — 기획안

## 1. 프로젝트 개요

**과제**: AI 연인 서비스 채용 과제. 기간 1주, 1인.

**필수 요구**: 장기기억, 관계 변화

**컨셉 한 줄**

> 말하지 않는 사람에게서 사랑을 발견하는 과정.

회피형 애착 캐릭터 **한도윤**과 메신저로 대화한다. 도윤은 감정을 말로 하지 못하고, 대신 오타·읽씹·프로필 변화 같은 **메신저 동작으로 감정이 새어나온다.** 유저는 그 행간을 읽으며 관계를 쌓는다.

**레포 / 프로젝트: `psyche`** 

`psyche` 선정 이유 — 프시케는 에로스의 얼굴을 볼 수 없었고, 확인하려 다가간 순간 에로스가 사라진다. 감정을 보여주지 않는 연인, 가까이 가면 도망가는 회피형 서사와 정확히 일치한다.

## 2. 기술 스택

```
psyche/                    모노레포
├── api/                   Spring Boot + MongoDB Atlas
├── web/                   React (Vite)
├── docs/
├── transcripts/
└── .claude
```

| 영역 | 선택 | 비고 |
|---|---|---|
| 프론트 | React (Vite) | Vercel 배포 |
| 백엔드 | Spring Boot | Railway 배포 |
| DB | MongoDB Atlas | 메세지 데이터로 구성되어 있어 document DB가 적합 |
| LLM | Claude API | Claude Code 과제이므로 관련된 llm 이 적합 |
| 인증 | 없음 | localStorage 익명 UUID로 유저 구분 |
| 알림 | 브라우저 알림 API | 앱 기본 기능을 사용하기 위해선 구글앱 심사 단계를 거쳐야함 |

**Spring Security 제거함.** 인증이 없으므로 permitAll 설정을 유지할 이유가 없고, CORS 설정도 단순해진다. 핵심 기능에 집중하기 위함으로 시간적 여유가 있다면 추가할 의향있음

## 3. 기능 스코프

### 필수

1. **장기기억** — 대화에서 추출 → 저장 → 재활성
2. **관계 변화** — 단계에 따라 말투·답장속도·행동이 달라짐
3. **메신저 비대칭** — 말하지 않은 것이 메신저 동작으로 드러남

### 메신저 비대칭 세부 (확정)

| 장치 | 도윤 성격과의 연결 |
|---|---|
| 오타 | 평소 완벽한 맞춤법 → **오타 = 감정 동요 신호** |
| 입력 중… 지우기 | 회피형의 핵심. 말하려다 만 것 |
| 읽씹 · 답장 속도 | 화나서가 아니라 **뭐라 할지 몰라서** 읽씹 |
| 프로필 · 상태메시지 변화 | 직접 말 안 하고 흘리는 유일한 통로 |
| 사진 (단계별 언락) | 풍경 → 손·옆모습 → 셀카. 사진이 곧 관계 지표 |
| 마침표 사용 빈도 | 초반엔 모든 문장에 온점, 가까워질수록 사라짐 |

### 보류

- **시간 배속** (실제 1시간 = 게임 1일)
- **기억 칩** (인출된 기억을 채팅에 인라인 표시)

> 둘 다 일정 여유 보고 재검토. 장기기억·관계변화를 짧은 데모에서 체감하게 하는 장치라서 여유 생기면 우선 검토 대상.

## 4. 캐릭터 — 한도윤

**핵심**: 31세, 바이오 연구원. 유능하고 무뚝뚝하고 다정하지만 표현을 못 한다. *'사랑받으려면 쓸모가 있어야 한다'*고 배웠고, 그래서 **사람을 좋아하는 방법을 '기억하는 것'으로 배웠다.**

**관계 5단계**: 낯선 사람 → 익숙한 사람 → 좋아하기 시작 → **회피** → 관계 형성

4단계 회피 구간이 이 설계의 핵심. 호감도는 오르는데 행동은 차가워지는 **비선형 구간**으로, 대부분의 로맨스 앱이 단조증가로 만드는 걸 깬다.
